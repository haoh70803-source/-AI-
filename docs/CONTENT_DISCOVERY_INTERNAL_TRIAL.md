# Content Discovery 内部试用说明

## FROZEN_SCOPE

本次内部试用冻结范围如下：

1. 内容搜索
2. 快速收录
3. 对标账号
4. 趋势机会
5. 我的选题
6. 今日内容线索 / 今天值得做
7. 推荐依据
8. 选题 → 内容项目
9. ContentProject → Studio

试用期间只接受 P0、P1；必要时处理范围明确的 P2。P3 新功能只记录，不开发。冻结范围之外的自动化、预测、长期偏好和新 Provider 不进入本次试用。

## 试用目标

验证真实创作者能否在没有工程人员解释的情况下，完成“发现方向 → 查看依据 → 保存选题 → 补充研究 → 开始创作”的完整流程。试用重点是观察理解成本和实际卡点，不是验证未来功能设想。

## 试用对象

- 日常负责选题、研究或内容创作的内部成员
- 尽量包含第一次使用本产品的人
- 观察员只记录行为和原话，不提前解释正确操作

## 三个核心概念

- 素材：我保存下来的参考内容。
- 选题：我正在考虑要做的内容方向。
- 内容项目：我已经正式开始创作的内容。
- 趋势机会：最近值得关注的方向。
- 今天值得做：根据已有真实数据整理出的优先创作方向。

## 试用原则

1. 从“内容发现”正式入口开始，不做功能讲解。
2. 让用户独立完成下方 6 个任务，每项单独计时。
3. 开发人员不要边操作边说“你应该点这里”。
4. 用户明确卡住后，先记录位置、停顿时间和用户原话，再提供帮助。
5. 试用结束后填写反馈模板，并按 P0–P3 汇总问题。

## 标准试用任务

### TASK 1 — 搜索真实方向

搜索一个自己实际关注的方向，例如 AI 获客、老板 IP、企业管理、教培或其他真实业务方向。

### TASK 2 — 从外部内容加入选题

找到一条值得参考的外部内容，完成：预览 → 加入选题。

### TASK 3 — 查看真实对标账号

添加一个真实对标账号，完成：添加 → 打开对标 → 显式加载作品 → 找一条值得看的内容。

### TASK 4 — 研究趋势机会

进入趋势机会，完成：查看趋势 → 查看依据 → 查看相关内容。

### TASK 5 — 理解今天值得做

进入“今日内容线索 / 今天值得做”，打开至少一条推荐依据。用户需要能说明：为什么推荐、为什么现在、和自己有什么关系。

### TASK 6 — 进入正式创作

从一个选题完成：继续研究 → 开始创作 → ContentProject → Studio。

## 人工监测重点

1. 用户打开 Content Discovery 后第一步做什么。
2. 搜索、趋势、对标中哪个入口最先使用。
3. 用户是否主动点击“今天值得做”。
4. 用户是否查看并理解推荐依据。
5. 用户是否信任推荐及其原因。
6. 用户是否理解“加入选题”。
7. 用户是否理解“开始研究”。
8. 用户是否理解“开始创作”。
9. 用户是否直接跳过选题层。
10. 用户进入 Studio 后是否觉得上下文断裂。

## 反馈与问题分级

反馈使用 [CONTENT_DISCOVERY_TRIAL_FEEDBACK.md](./CONTENT_DISCOVERY_TRIAL_FEEDBACK.md)，问题汇总使用 [CONTENT_DISCOVERY_TRIAL_ISSUES.md](./CONTENT_DISCOVERY_TRIAL_ISSUES.md)。保留用户原话，不要提前替用户总结。

- P0：无法完成主链、数据或安全问题、误收费。
- P1：关键流程无法理解或明显阻塞。
- P2：视觉、文案、移动端或效率问题。
- P3：未来功能建议，只记录不开发。

## 外部服务说明

打开内容发现、推荐详情或已有趋势不会自动调用外部服务。只有用户明确点击搜索、刷新趋势、加载对标作品、生成 AI 内容或收录内容时，才会发起对应请求并可能产生费用。

真实 Kimi 尚无可用凭证，不创建假验收结果；deterministic 内容线索不受影响。
