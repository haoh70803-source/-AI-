# 工作台 Agent 角色、能力与设计审计

- 审计日期：2026-10-09（Asia/Singapore）
- 范围：项目对话、上下文、Skill、权限、资料读取、联网检索、成果修订与当前本机运行状态。
- 验证等级：V0。依据代码阅读与本机只读健康检查；审计未运行代码测试、未调用第三方 API。
- 性质：审计发现与建议，不是 Governance Update，不授权实施、重构或扩展产品范围。
- 权威依据：[PRODUCT.md](../../PRODUCT.md)、[ARCHITECTURE.md](../../ARCHITECTURE.md)、[LEGACY.md](../../LEGACY.md)、[AGENTS.md](../../AGENTS.md)。与权威规则不一致的现状记为 `CURRENT IMPLEMENTATION GAP`。

## 1. 总体判断与角色定位

**PRODUCT PRINCIPLE**：产品以项目为长期工作容器，对话承载持续协作，按需使用资料、研究、可选技能和工具，形成可持续修改、保存的成果。通用 Agent 不以选择默认 Method 为前提。

**审计建议**：Agent 应当是项目中的主要协作者：理解当前项目和用户目标，在授权范围内主动完成工作，遇到关键不确定性才询问，并把结果沉淀为项目成果。

应承担五项职责：

1. **理解任务**：识别目标，沿用已有要求，区分新任务、继续推进和局部修改。
2. **使用信息**：读取项目资料、历史决定、研究结果和当前成果，说明依据与缺口。
3. **推进工作**：自行完成常规判断，复杂任务分步骤执行，失败后调整路径。
4. **交付成果**：输出可用正文、模板、分析或方案，支持保存、修订和继续工作。
5. **维护连续性**：记住已选方向、表达偏好、重要事实、未完成事项和当前成果版本。

用户掌握目标、事实和重要决定；Agent 负责常规执行判断。发布、删除、共享范围变化等高影响操作仍须明确授权。**INVARIANT**：服务端权限与范围检查不能由 Prompt 或 UI 隐藏代替。

**CURRENT IMPLEMENTATION GAP**：目前已有项目协作基础，但运行仍偏内容创作，很多能力通过预设代码流程触发。最近的“先交付、少追问”提示词调整方向正确，仍需上下文、执行机制和界面共同支持。

## 3. 主要问题与完善建议

### A01：界面将不同提示统一呈现为“需要确认”

**CURRENT IMPLEMENTATION**：回复界面把所有 `message.warnings` 放在“需要确认”标题下。警告既可能来自事实风险，也可能来自上下文截断、资料不可读或检索失败。

**影响**：即使模型不再追问，界面仍可能让用户认为每轮都需要确认。仅修改提示词不足以解决问题。

**建议**：按性质区分显示：用户决定、事实待核实、资料不足、运行失败、普通提示。只有需要用户决定的事项提供确认入口；其他提示说明影响及可继续完成的部分。

依据：[回复界面](../../apps/web/components/projects/studio-default-method.tsx)、[Agent 警告与结果处理](../../apps/web/server/assistant/service.ts)。

### A02：通用对话没有完整接入已确认事实

**CURRENT IMPLEMENTATION GAP**：通用助手上下文返回 `ownFacts: []`，后置事实检查依赖该数组；这一通用路径未完整带入已确认信息和创作者事实引用。

**影响推断**：已有事实可能再次被要求核实，Agent 也难以稳定沿用用户提供的真实背景。具体误报范围仍需用真实案例验证。

**建议**：补齐事实来源、归属和更新时间，区分已确认事实、当前要求、临时补充、外部参考和 AI 推断。不得将临时聊天、AI 推断或外部案例自动转成用户已确认事实。

依据：[通用上下文构建](../../apps/web/server/ai/control/context-builder-v2.ts)、[回复后置检查](../../apps/web/server/assistant/service.ts)、[事实检查](../../apps/web/server/studio/fact-safety.ts)。

### A03：通用项目定位与内容创作范围限制不一致

**CURRENT IMPLEMENTATION GAP**：提示词仍定义为“内部内容研究与创作协作助手”；ScopeGate 使用内容相关关键词和显式拒绝规则判断范围，部分百科或历史人物问题可能触发拒绝，即使它们属于当前项目研究。

**建议**：按项目目标、用户任务和可用能力判断相关性。内容创作可以作为重点场景，表达要求由任务或 Skill 提供。范围判断的产品收敛应成为明确模块任务；安全权限边界继续保留。

依据：[系统提示词](../../apps/web/server/assistant/service.ts)、[范围判断](../../apps/web/server/ai/control/scope-gate.ts)。

### A04：执行仍以固定编排为主，缺少通用多步任务机制

**CURRENT IMPLEMENTATION GAP**：主流程判断作品链接或搜索请求，执行预设处理，组装上下文，再调用模型和检查回复。尚未看到通用的“计划 → 选择工具 → 观察结果 → 调整步骤 → 继续执行”循环。作品链接进入媒体处理时，会跳过这一轮搜索路径。

**影响**：例如“读取视频、核对数据、生成总结”，尚不能据此认定系统会自主完成整个任务链。

**建议**：先打通少量高频任务，复用资料、研究、成果和现有 Provider 能力，再逐步收敛工具执行机制。工具执行需有权限、参数校验、状态、超时、错误处理和成本边界。

依据：[项目 Agent 主流程](../../apps/web/server/assistant/service.ts)、[媒体处理](../../apps/web/server/assistant/media-link.ts)、[联网检索](../../apps/web/server/assistant/web-search.ts)。

### A05：Skill 解析状态与实际执行尚未完全收口

**CURRENT IMPLEMENTATION GAP**：通用路径调用 Dry Run 解析器，但技能上下文仍由 `methods` 直接构建。入口接收单个 `skillVersionId`，默认项目技能只取第一项，不能视为完整多技能组合执行。

**待核实风险**：显示“本次跳过”的技能是否仍进入模型上下文，需要定向验证，不能仅凭状态展示认定已正确跳过。

**建议**：使用状态与实际执行一致；跳过技能不影响本轮；轻微冲突按当前用户要求自行处理，实质冲突才询问。0 Skill 仍能工作。

依据：[Skill 上下文接入](../../apps/web/server/ai/control/context-builder-v2.ts)、[Skill Resolver](../../apps/web/server/ai/skill-resolver.ts)、[历史迁移账本](agent-skill-runtime-migration-v1.md)。历史账本用于追溯，不能覆盖权威规则。

### A06：长期项目记忆主要是有限摘录

**CURRENT IMPLEMENTATION**：旧对话摘要主要取每条消息前 240 字，再保存有限长度的摘录；近期对话另有预算保护。

**影响推断**：已选方向、已否定方案、特殊要求可能遗漏或失去上下文，摘录不能等同于可靠的项目记忆。

**建议**：逐步维护项目目标、已定要求、当前成果、未解决问题和最近决定。记录来源，允许用户修改或撤销，不把 AI 猜测持久化为事实。

依据：[历史对话处理](../../apps/web/server/assistant/service.ts)、[上下文预算](../../apps/web/server/assistant/context-budget.ts)。

### A07：当前后台运行条件不足以支持完整验收

**CURRENT IMPLEMENTATION**：2026-10-09 本轮只读健康检查显示：

| 项目 | 检查结果 |
| --- | --- |
| 环境 | LOCAL_LIVE，用户入口为 http://localhost:3022 |
| 外部调用 | enabled |
| 数据库与文件存储 | 正常 |
| Redis | UNREACHABLE |
| Worker | MISSING |
| 后台任务 | disabled |

**影响**：可以测试部分同步调用，不能宣称采集、转写等后台流程已完整可用。模型、红狐、ASR 的配置状态也不等同于第三方请求实际成功。

**建议**：恢复并核对后台依赖后再开展完整验收。长任务完成应关联原请求，提供继续处理入口，减少要求用户反复发送“继续转写”。

依据：本轮 `/api/health/ready` 与 `/api/dev/runtime-health` 只读响应；[媒体任务等待与返回](../../apps/web/server/assistant/media-link.ts)。以上为审计时点快照，不是持续运行保证。

### A08：成果与能力展示需要继续收敛

**CURRENT IMPLEMENTATION GAP**：通用成果仅有 TEXT；旧稿件、Canvas 等路径仍与通用成果并存。知识库默认适配器返回 unsupported。

**建议**：对话负责推进，成果对象承载长期内容。先完善文本成果的保存、引用、修订和版本体验，再按明确需求扩展类型。UI 展示真实能力状态，避免让用户误以为知识库、后台服务或完整研究能力已可用。

依据：[成果 Schema](../../packages/db/prisma/schema.prisma)、[成果服务](../../apps/web/server/artifacts/service.ts)、[知识库适配器](../../apps/web/server/assistant/references.ts)。旧路径处置遵循 LEGACY.md，本审计不授权删除。

## 4. 回复与交互设计建议

回复规则经本轮用户明确调整：在安全、事实和权限边界内，优先遵循用户本轮的明确要求；信息足够就完成，缺少关键输入就最少量询问，只有用户需要模板时才交付模板。历史偏好、默认表达和 Skill 不覆盖本轮明确要求。

交付应当给用户明确的成果或可执行方向，减少用户需要补做的核心工作。成稿需完成观点、角度、论证及正文等核心判断；执行建议需明确推荐行动、实际步骤和预期交付物。不能以大量占位符、空框架或笼统建议代替交付，也不能把模板说成可直接使用的成稿。

| 用户要求 | 合适的首次交付 |
| --- | --- |
| 写文案，主题明确 | 完整初稿。 |
| 写文案，主题缺失 | 先检查对话和选中资料；仍未知时只问一个关键问题，给两个简短回答例子。 |
| 用户明确要模板 | 交付适用模板，清楚标明待填事实，不称其为完成的成稿。 |
| 用户要求方案或执行方向 | 推荐明确行动，给实际步骤和预期交付物。 |
| 审计或研究 | 已核实发现、证据和缺口。 |
| 修改已有成果 | 修改后的版本，保留未要求更改的部分。 |
| 处理视频资料 | 真实执行进度，完成后继续原任务。 |
| 存在关键未知事实 | 完成可确定部分，再询问最少的必要问题。 |

常规结构、措辞、语气、长度和可逆修改由 Agent 判断。正文完成即可自然结束，不默认追加方向选择、继续邀请或确认提示。实质分歧可以先完成推荐版本，再给少量可选方向；连续改稿不重复提供选项。

还需完善长资料读取：上下文预算与截断已有基础，后续应优先检索任务相关段落，并准确说明阅读覆盖范围，不能把读取了部分内容说成审阅全文。

## 5. 建议推进顺序

以下为建议，不是已批准施工计划。

| 优先级 | 建议工作 | 验收重点 |
| --- | --- | --- |
| 第一批 | 恢复后台依赖；区分提示与确认；接入已确认事实 | 不误报可用，不重复确认已知信息。 |
| 第二批 | 打通“读取资料 → 研究核对 → 生成 → 保存 → 修改” | 一个用户请求能够持续推进，阶段状态可追踪。 |
| 第三批 | 收口 Skill 实际执行；改善项目记忆和长资料读取 | 技能状态可信，长期要求不丢失，阅读范围准确。 |
| 后续明确任务 | 扩展成果类型及其他规划能力 | 按产品阶段推进，避免提前扩张。 |

**FUTURE**：内容经营域、许可证与本地优先桌面交付仍遵循权威文档阶段安排。本审计不授权提前实施，也不建议以本次审计为由全仓重构。

## 6. 后续验收建议

使用真实模型行为验证与服务/API 验证分别证明回复质量和功能执行，不能用 Mock 回复测试替代真实模型评估。

1. 主题缺失的创作请求：先使用对话和选中资料，仍未知时只问一个关键问题并给两个短例子，不先发空框架或问卷；仅在用户需要时交付模板。
2. 主题明确的请求：直接生成完整内容，不默认追加选择或确认。
3. 连续改稿：沿用既定要求，只修改指定内容，不重新收集需求。
4. 已确认事实：能够沿用并追溯来源，不重复要求确认，不把外部事实写成用户经历。
5. 真正关键的未知信息：完成可确定部分，问题最少且解释具体影响。
6. 多步资料任务：执行状态真实；后台失败或凭证不可用时不虚构结果。
7. Skill：0 Skill 可工作，使用与跳过状态和实际上下文一致。
8. 长期协作：已定方向和重要要求能延续，支持修正或撤销。
9. 成果修订：保存和应用目标明确，版本冲突不覆盖用户工作。
10. 权限边界：只读取获准内容，高影响操作需授权，不能由提示词绕过。
11. 本轮要求完整性：例如“3 个不同角度开头 → 自选一个展开 → 约 60 秒口播 → 发布标题”，信息足够时一次交付全部要求；开头应有内容角度区别，未完成正文不声称可以直接读或保证时长。
12. 减负验收：检查用户拿到结果后还需要补做多少核心工作；观点、论证和核心步骤不留作填空，交付物应当可用或执行方向明确。必要的事实补充与授权可以请求，但常规表达判断由 Agent 完成。

近期目标应是：用户说一次目标，Agent 先完成可做的工作，可靠使用已有信息，在少量必要节点请求决定，让成果持续积累。
