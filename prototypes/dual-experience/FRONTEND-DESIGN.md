## 2. 统一应用外壳

```text
AppShell
├─ BrandMark：原 Logo 红点与三条水平弧线
├─ IconRail：64px 应用导航
│  ├─ 首页
│  ├─ AI 创作（项目工作区）
│  ├─ 内容中心
│  └─ 数据中台
├─ Topbar：品牌、主题切换、消息
└─ Main：页面视图
   ├─ Home
   ├─ Project Workspace
   ├─ Content Center
   └─ Analytics
      ├─ 模块导航：数据总览 / 行为分析 / 数据范围 / 相关工作
      ├─ 模块工具栏：面包屑、视图、搜索、周期、导出
      └─ 统计内容区
```

应用导航负责跨模块跳转，数据模块导航负责当前分析视图和范围。数据模块内部保留参考图的宽侧栏结构；首页继续只有窄图标栏。进入数据中台时才出现模块导航，不将两个侧栏同时推广到所有页面。

现有原型 `app.js` 增加页面渲染映射，避免不断扩展内嵌三元分支。数据模块只提供页面内容并消费共享 icon、footer、modal、toast、detail，不新建第二套壳、弹窗或主题管理。

正式接入优先扩展现有 SidebarFoundation、appearance.ts、StudioShell、ArtifactWindow、资料与内容组件。原型代码不会直接成为新的平行业务系统。

## 7. 视觉一致性的具体规则

- 外壳：同一个 Logo、64px 导航、72px 顶栏、图标描边、主题切换组件。
- 表面：数据卡片消费已有 `--surface`、`--border`、`--ink`、`--muted`，不使用另一套全局黑底或蓝底。
- 控件：搜索、周期选择、导出、图标按钮、详情弹窗和反馈都复用原型组件样式与行为。
- 字体：同一个系统字体栈。首页可以用展示级标题，数据区域用清晰指标级标题和数字，避免把首页 68px 标题套到所有统计卡。
- 图表：线、柱、扇区、热力色阶共享 `--series-*` 与 `--heat-rgb`。使用低饱和暖灰、陶土、灰绿；品牌红仍用于导航选中和少量重点。
- 卡片：保留参考布局的网格、内容顺序和图形格式；统一 12px 圆角与细边界。
- 活跃卡：保留参考图的特殊色块卡片格式，将蓝色适配为品牌体系的暖灰底，不复制另一套科技蓝系统。
- 主题：两视图的布局和交互均与主题解耦，原型验证切换后卡片坐标与宽度不变。
- 状态：可见选中、hover、focus、tooltip、空搜索结果、详情、导出反馈；图表不能只是截图。

## 8. 实现文件与依赖关系

```text
index.html
├─ tokens.css：系统颜色、密度、间距
├─ styles.css：应用外壳、共享组件与原有页面
├─ analytics.css：数据模块布局与图形表现
└─ app.js：共享外壳与路由、原有页面
   └─ analytics.js：两种数据布局、模块状态与交互
      └─ charts.js：折线、柱状、扇形环图、堆叠、热力、矩阵
```

先搜索现有视频分析图表能力：`video-analytics-workspace.tsx` 已有 SVG 趋势与分布；`video-center.tsx` 已有柱状趋势与缺失数据表达。它们是带生产数据依赖的 React 组件，本轮因独立原型边界不直接导入，也不改其实现。charts.js 只服务本轮静态实验，不新增依赖或服务端抽象。正式落地须复用或适配现有能力。

模块状态：分析视图由 URL 管理，范围/周期/指标/图例/搜索由数据模块管理；主题由共用系统管理。数据范围和时间范围改变主图及总览示例数值；设备占比、留存、月周日观察等目前保留固定演示序列，不是完整统一统计查询结果。

## 9. 响应式及接入要求

- 桌面保留参考网格：总览 4→1→3 区块；行为分析上/下两排三列。
- 平板隐藏数据模块宽导航，保留顶部两视图入口；图表保持顺序自适应折行。
- 手机总览 KPI 两列，后续统计纵向排列；行为顶部趋势通栏、热力和活跃两列，下排纵向。底部保留四模块导航。
- SVG 分段、数据点和热力按钮有可读标签，支持键盘焦点；悬停提示、主题和选择状态不只依赖颜色。
- 正式接入的数据合同应包含指标值、单位、统计口径、时间范围、更新时间、来源与覆盖率；空值、零值与未采集要区分。
- 权限、数据范围及项目访问继续由服务端 scope/RBAC 检查。本轮仅演示交互，不改变 API、数据库或权威文档。
- 首次正式落地按模块定向验证；全局 CSS 收敛和域治理仍需独立明确任务，不借 UI 施工扩大范围。

## 10. 全量接口登记与视频拆解页面
本轮在当前工作区静态扫描196个API路由文件，登记282个HTTP入口及571个server导出函数。函数仅核对直接路由调用；没有直接入口的函数可能为内部/间接实现，不自动新增接口。全量登记见API-COVERAGE.md，机器清单API-INVENTORY.json，六项缺口/核对设计见API-GAP-DESIGN.md。
新增#teardown、#settings、#capabilities。研究页提供视频拆解入口；拆解页包含抖音输入、五阶段进度、个人历史、原视频预览位置、逐段原文定位、语义时间轴、主线、优点、风险、传播假设、趋势缺失说明、作者比较、导出和加入项目。加入项目后展示对应项目名称与报告引用。只读演示禁用写操作，失败/重试/取消/更新由手动状态演示触发，没有执行真实后台工作。
功能地图逐方法登记页面承接、源码和直接调用，支持搜索/模块筛选/分页/操作说明；设置页按服务、成员、用量、登录、存储与兼容范围提供操作设计入口。功能地图是交付审查工具，不建议保留在正式用户主导航。
44张截图：9个视图的深浅桌面与手机36张、成果手机面板2张、拆解比较/失败/分享状态6张。verify-coverage.mjs本轮55项定向检查通过；之前验证文件为历史基线。

## 数据投影与补充契约（当前增量）

analytics-adapter.js 在隔离原型内将日度契约样例投影到现有图表组件；它不连接正式服务，也不新增正式业务中心。今日快照、周期趋势、账号排名、平台占比与互动构成共享字段与聚合口径，账号和周期选择作用于同一组记录。缺失值、负净增粉及无观测记录分别保留相应语义。

页面提供补充方案和现有能力两种预览，共用布局。小时热力、留存矩阵、设备圆环的来源尚缺，补充设计明确采集粒度、权限、来源限制与可用状态；详见 ANALYTICS-ADAPTATION.md。正式接入先复用现有 video-data 与图表能力，再按模块授权实施契约扩展。

当前 verify-adaptation.mjs 为 66 项检查、48 张截图。新增 4 张为深浅主题的现有能力桌面与手机视图；上述 55 项/44 张为历史结果。
