# 素材处理 UX

## 页面顺序

素材详情保持固定阅读顺序：

1. 媒体
2. 处理状态
3. 素材信息
4. 转写结果
5. 智能整理
6. 标签、素材集和项目操作

高级任务记录和媒体技术信息默认折叠，仅用于排查问题。

## 处理状态

页面不保存第二套状态，也不显示虚构百分比。状态由 `SourceItem`、`SourceAsset`、`IngestJob` 和 `Transcript` 共同计算：

- `WAITING`：等待前序任务或队列执行。
- `PROCESSING`：真实 Job 正在运行。
- `SUCCEEDED`：对应媒体或结果已持久化。
- `FAILED`：最新对应任务失败。
- `SKIPPED`：当前素材或配置不需要该步骤。

运行中只显示不确定进度条和真实阶段说明。只有存在可靠 `startedAt` / `finishedAt` 时，才在高级记录中显示耗时。

## 自动刷新

- 轮询间隔：2.5 秒。
- 仅素材详情且仅处理中启用。
- 浏览器页面隐藏时暂停实际请求。
- 完成或失败后停止，并刷新 Server Component 一次。
- 组件卸载时取消请求、定时器和事件监听。
- 轮询接口只返回状态、Transcript 是否存在和变更指纹，不返回媒体 URL、Provider 原始响应或 Secret。

## 操作后的下一步

- 收录成功：显示可关闭通知，并链接到素材详情。
- 加入选题成功：显示选题名称，并链接到选题详情。
- 创建项目成功：直接进入项目工作台，不再叠加重复提示。
- 审核和发布仍沿用各自页面已有的轻量状态反馈。

所有通知动作只能指向系统内可信路由。

## Transcript → Smart Material Analysis

- 转写完成后只显示手动“开始智能整理”，不会自动产生 Kimi 调用费用。
- 智能整理默认先展示标题、主题、摘要与核心观点，完整字段按需展开。
- AI 结果与 RedFox 原始信息、Transcript 分开保存和显示；人工编辑不回写原始数据。
- 重新整理会创建新版本并保留旧版本。Transcript 后续更新时只显示 stale 提示，不自动重新整理。
- 整理完成后的“基于这条素材创作”复用现有 ContentProject / Studio 流程，不自动生成 Brief 或母稿。

## 后续边界

以下事项不属于 V1.2A：

- 内容结构识别和二创建议。
- 本地存储位置选择与迁移工具。
- RedFox 趋势、账号作品和搜索结果的统一 freshness 策略。
