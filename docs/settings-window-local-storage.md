## 真正的本机文件存储

当前独立环境启用 `LOCAL_FILESYSTEM`，复用已有媒体中转存储的上传、签名访问与权限校验，不再依赖 S3 保存新上传文件。

根目录为：

`D:\Documents\ChatGPT\内容生产中心-account\.local-data`

各公司使用 `workspaces/<workspaceId>/locations/<directory>` 独立目录。配置与文件均在本机，`.local-data` 已 Git 忽略。

页面支持：当前路径、复制路径、现有目录选择、新建命名目录、写入/读取验证、磁盘可用空间、已存文件数量/体积、切换位置、恢复默认位置。

目录切换采用复制、SHA-256 校验、原子切换配置，原目录保留。目标已有同名不同内容文件时停止，不覆盖；拒绝路径穿越、Windows ADS、符号链接与目录联接。上传、删除、迁移共享 PostgreSQL advisory transaction lock，进程异常退出也会释放，避免残留锁文件造成永久锁死。

同时修复既有媒体访问中的下载扩展名问题：保留原始文件名，支持 UTF-8 文件名；增加 Range/206/416 响应以支持媒体分段读取。

## 明确边界

- 当前目录选择限定在当前公司专属本机数据范围内。没有实现桌面系统级的“任意磁盘/任意目录选择器”。
- 移动的是上传资料与媒体文件，不是数据库或软件安装位置。账号、项目、对话、文本成果仍存于现有本机 PostgreSQL。
- “本机”指运行应用服务的电脑；若用户从其他电脑通过浏览器访问，不代表文件保存到那台浏览器电脑。
- 本轮未迁移任何主项目或云端历史文件。独立环境原先没有接入真实 S3 数据；不得把此候选直接当作 S3→本机的完整迁移工具。
- 本机私有文件地址不能直接作为第三方云端转录的公网地址；本地转录与已有支持二进制上传的协议应按真实能力使用。
- 未修改数据库 Schema，无新增迁移。

- Web typecheck、变更 TypeScript 定向 ESLint、git diff --check 已检查。没有执行全仓 Playwright。

独立测试所生成的文件和公司有明确“验收”标识，仅用于该隔离数据库与本机目录的验证。
